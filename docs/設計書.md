# Markdown Quick Memo 設計書

## 目的

Windowsのグローバルホットキーから短時間で表示でき、Markdown原文を壊さず、滑らかなスクロールとKaTeXによる数式表示を提供する。

## 技術構成

| 層 | 技術 | 責務 |
| --- | --- | --- |
| 常駐ランチャー | Rust / Win32 | `RegisterHotKey`、本体の非表示ウォームアップ、完全終了後の再起動 |
| デスクトップシェル | Rust / Tauri 2 | 単一起動、ウィンドウ制御、ファイル操作、保存、PDF、OS連携 |
| WebView | WebView2 | HTML、CSS、スクロール、IME、印刷 |
| エディター | TypeScript / CodeMirror 6 | 本文、選択、Undo・Redo、カーソル、入力支援、Decoration |
| 数式 | KaTeX | インライン・独立数式の表示 |

## 状態の所有

編集中の次の状態はCodeMirrorの`EditorState`だけが所有する。

- Markdown本文
- 選択範囲
- Undo・Redo履歴
- カーソル
- スクロール位置

Rust側へ本文を入力ごと、一定時間ごと、または非表示時に同期しない。Rust側は現在のファイルパス、保存要求、ウィンドウ状態、起動要求などOS境界の状態だけを管理する。

保存・PDF出力など本文が必要な操作では、TypeScriptからRustへ全文と単調増加するリビジョン番号を渡す。保存完了時のリビジョンがCodeMirror側の現行値と一致する場合だけ未保存状態を解除する。保存中に編集された場合、保存結果は有効でも未保存状態を維持する。

## プロセス構成

### Rustホットキーランチャー

`MarkdownQuickMemoHotkey.exe`は本文を持たない約300 KBの常駐プロセスである。

1. `%LOCALAPPDATA%\com.markdownquickmemo.app\hotkey.txt`からキー設定を読む。
2. Win32の`RegisterHotKey`でキーを登録する。
3. `MarkdownQuickMemo.exe --background`を起動し、WebView2とCodeMirrorを非表示で初期化する。
4. ホットキー押下時に`MarkdownQuickMemo.exe --hotkey-triggered`を起動する。
5. 本体が存在する場合はTauri単一起動プラグインが既存プロセスへ要求を転送し、存在しない場合は新規起動する。

ランチャーはメッセージ専用ウィンドウを持つが、画面、タスクバー、Alt+Tabへ表示しない。本体からのキー変更はWin32メッセージで受ける。新しいキーの登録に失敗した場合は以前のキーへ戻し、成功した設定だけをファイルへ保存する。

ランチャーと本体の間でMarkdown本文や編集状態は同期しない。

### Tauri本体

Tauri単一起動プラグインを本体プロセスの権威とする。二重起動要求では次を既存プロセスへ転送する。

- 表示要求
- ホットキー発火通知
- ファイル起動パス
- ホットキー登録失敗情報

ログオンタスクの`MultipleInstances IgnoreNew`は、ランチャー多重起動に対する外側の補助防御である。

## ライフサイクル

### ログオン

```text
ログオンタスク
  -> Rustランチャー
  -> RegisterHotKey
  -> Tauri本体 --background
  -> WebView2初期化
  -> CodeMirror初期化
  -> 非表示待機
```

### 表示

```text
Ctrl+Alt+M
  -> ランチャーが本体EXEを起動
  -> Tauri単一起動が既存プロセスへ転送
  -> show / unminimize / focus
  -> CodeMirrorへfocus
```

本体起動中でなければ、新しい本体が起動して初期化完了後に表示する。

### 非表示と完全終了

- `Ctrl + Q`: Tauriの`hide()`を使用する。1ピクセル透明化、画面外移動、Opacity 0による疑似非表示は使用しない。
- `Alt + F4`: 保存確認後にTauri本体を完全終了する。Rustランチャーは残るため、次のホットキーで本体を再起動できる。

WebView2は可視化時の自動再開を基本とする。COM経由の明示的Resumeは、実機で自動再開失敗が再現した場合だけ追加する。

## ファイル処理

- 読み込みはUTF-8 BOMの有無を許容する。
- 保存はUTF-8 BOMなしとする。
- 拡張子がない場合だけ`.md`を付ける。
- 保存先と同じフォルダへ一時ファイルを書き、`sync_all`後に置換する。
- Windowsでは`MoveFileExW`の`MOVEFILE_REPLACE_EXISTING`と`MOVEFILE_WRITE_THROUGH`を使用する。
- 保存失敗時は既存ファイルを保持する。
- 保存先がある文書は最後の入力から1秒後に自動保存する。未保存の新規文書では保存ダイアログを自動表示しない。
- 手動保存と自動保存は直列化し、保存中の追加入力は最新リビジョンを改めて自動保存する。自動保存失敗時は未保存状態を維持し、入力なしで再試行を繰り返さない。
- ファイル名変更では既存ファイルを上書きしない。
- 保存先表示は保存済みファイルの親フォルダだけをExplorerへ渡す。

新規作成・ファイルを開く・終了では、未保存時に「保存」「保存せず続行」「キャンセル」を区別する。ファイルを開く操作では、先にファイル選択を行い、選択キャンセル後に保存・破棄だけが成立しないようにする。

## CodeMirror編集

CodeMirror 6の`EditorView`と`EditorState`を中心に構成する。Markdown構文、検索、Undo・Redo、選択範囲、IME compositionはCodeMirrorへ委ねる。

上部の常設ボタンから閲覧モードへ切り替える。切替には`Compartment`と`EditorState.readOnly`を使用し、閲覧中の文書変更transactionを拒否する。選択、コピー、検索、スクロール、目次移動、リンク操作は維持する。閲覧状態は実行中の文書切替では維持するが、再起動後は編集モードから開始する。

検索はCodeMirror標準の検索状態、ハイライト、検索・置換コマンドを維持し、パネルだけを編集欄右上のフローティング表示にする。検索、置換、前後移動、全選択、大文字・小文字、正規表現、単語単位と読み上げ文言を日本語表示にする。公開検索APIの検索カーソルで現在位置と総件数を数え、`N / M 件`として検索条件、選択、置換、本文変更へ追従させる。空検索、無効な正規表現、該当なしは`0 / 0 件`とする。高優先度の`Mod-f`キーマップで、閉じている場合は表示し、開いている場合は閉じる。

### Decoration

次をDecorationとして表示する。

- 見出し
- 強調、斜体、取り消し線
- インラインコード、コードブロック
- リスト、チェックリスト、引用
- 表、水平線
- インライン・独立数式

編集モードでは、カーソルまたは選択範囲と重なる要素の編集用Markdown記号だけを原文へ戻し、見出し、リスト、引用、リンク、コードなどの外側の装飾は維持する。数式と水平線は装飾と原文を併記する。閲覧モードでは選択にかかわらず装飾表示だけを維持する。Decoration DOMは文書へ挿入せず、保存内容へ含めない。

高さが変化する独立数式を含むDecorationは`EditorState`の`StateField`で管理する。CodeMirrorが禁止しているViewPlugin経由のブロックDecorationは使用しない。DecorationSetは文書状態に対して構築し、実DOMの生成と配置はCodeMirrorの表示範囲管理へ委ねる。

左側の行番号ガターは表示しない。現在のキャレット位置と文字数・単語数、閲覧モード切替は上部ツールバーへ表示する。新規、開く、保存を独立した上部ボタンにはせず、既存のキーボードショートカットと右上の主操作一覧から実行する。三点メニューにはREADMEで定義したアプリ固有ショートカットをすべて表示し、メニュー外のクリックまたはメニュー操作の実行で閉じる。現在のグローバルホットキーは初期化・設定変更時に表示へ同期する。

表はMarkdown原文の行とセル範囲へDecorationを適用し、罫線と列配置を維持したままセル本文をCodeMirrorで直接編集する。区切り線、パイプ、セル外側の空白は非表示にするが原文には保持する。セル内のインラインコードとインライン数式にも通常のDecorationを適用する。引用は階層ごとに一文字幅ずつ右へ4ピクセルの縦線を追加し、階層によらずコードブロックと同じ`--surface-muted`背景を使用する。編集中も縦線をWidgetで残してMarkdown原文の`>`と同時表示し、半角・全角の長文は引用接頭辞の後ろへ揃えて折り返す。

ルートで`font-synthesis: none`を使用しているため、斜体Decorationだけは`font-synthesis: style`を許可する。これにより斜体フォントを持たない日本語フォントでも疑似斜体を使用し、英字と日本語で一貫して斜体を表示する。

### 目次

CodeMirrorのMarkdown構文木から`ATXHeading1`～`ATXHeading6`を抽出し、見出しレベル、表示名、文書位置をフロントエンド内だけで保持する。コードフェンス内の記号、Setext見出し、空見出しは対象にしない。同名見出しは文書位置で区別する。表示時は直前にある最も近い浅い見出しを親とする階層へ変換し、見出しレベルが飛んでいても階層を維持する。

文書読込時と編集中の目次更新では、CodeMirrorの増分解析を30ミリ秒単位で文書末尾まで進める。未完了の場合は短時間後に続きを実行し、解析中に本文が変わった場合は古い処理を中止する。編集中の開始は文字数・単語数と同じ120ミリ秒の遅延を使用する。位置に依存しない階層キーで実行中の開閉状態を保持し、存在しなくなった見出しの状態だけを破棄する。レベル1～3で子を持つ見出しには開閉ボタンを表示し、その子孫全体を開閉する。目次情報と開閉状態はMarkdown原文、Rust状態、保存ファイルへ含めない。

項目を選択すると該当位置へCodeMirrorのカーソルを移動し、`EditorView.scrollIntoView`の`y: "center"`とフォーカスを適用する。文書先頭・末尾付近でも中央に近い位置まで移動できるよう`scrollPastEnd`を有効にする。

目次項目は階層ごとの縦線とインデントで表し、長い表示名は目次幅で折り返す。項目一覧は残りの高さを占有し、内容が高さを超えた場合は目次内だけを縦スクロールする。

画面幅1200ピクセル以上では右側の列へ常時表示する。狭い画面では右端14ピクセルを残したオーバーレイとし、マウスオーバーまたはキーボードフォーカスで展開する。幅は実行中だけ240～480ピクセルの範囲で40ピクセルずつ変更でき、`Ctrl + ←`を拡大、`Ctrl + →`を縮小に割り当てる。検索欄や設定欄などの入力要素ではこの割り当てを使用しない。狭い画面ではビューポート幅を超えないよう制限する。見出しがない場合は目次領域を作らず、編集欄を全幅で使用する。

`Ctrl + Shift + L`で目次操作を開始・終了する。開始時は狭い画面でも目次を展開し、折りたたまれていない最上部の項目を選択して該当見出しへ移動する。操作中の`Ctrl + ↑`と`Ctrl + ↓`は表示中の項目間を移動し、CodeMirrorのカーソルと表示位置も同時に更新する。キーを600ミリ秒以上保持すると1回につき2項目、1200ミリ秒以上では4項目へ加速し、キーを離すかフォーカスを失った時点でリセットする。目次は視覚的な選択状態だけを持ち、CodeMirrorのフォーカスを維持して通常文字とIME入力を妨げない。再描画時は階層キーで選択を維持し、対象が消えた場合は最上部の表示中項目へ戻す。

### 入力支援

入力支援はCodeMirror transactionとしてMarkdown原文へ適用し、Undo・Redo可能にする。

- リスト、番号付きリスト、チェックリストの継続と終了
- 引用の継続と終了
- `Tab` / `Shift + Tab`による階層変更
- `Shift + Enter`の単純改行
- 行頭インデントの継続
- 対括弧、引用符、バッククォート
- コードフェンスの閉じ記号生成

コードフェンス内ではMarkdown構造の補完を抑止する。

空の選択位置で対記号を補完した場合、生成した閉じ記号と位置を次のテキスト入力1回分だけ保持する。直後に同じ閉じ記号が入力され、カーソル位置と生成文字が一致する場合は本文を変更せずカーソルだけ右へ移動する。別文字、貼り付け、位置変更後の入力では保持状態を破棄し、既存の閉じ記号は自動補完として扱わない。

内容のあるリスト行でEnterを押すと同じリスト構造を次行へ継続し、その空項目で再度Enterを押すと、余分な空行を追加せずリスト記号だけを削除する。

内容のある引用行でEnterを押すと同じ引用深度を次行へ継続する。空の引用行では改行せず、Enterごとに同じ行で一階層ずつ浅くして最浅階層から引用を終了する。空引用の接頭辞直後でBackspaceを押した場合は、深度にかかわらず末尾の半角スペースだけを削除する。

入力支援のEnter、Tab、十字キーはCodeMirror標準キーマップより高い優先順位で処理する。TabとShift+Tabはリスト行では階層を変更し、通常行では文書と選択範囲を変更せず処理済みとして、エディター外へのフォーカス移動を防ぐ。左右キーは視覚上のDecorationに依存せずMarkdown原文の論理位置を一文字ずつ移動し、上下キーは通常どおり一行ずつ移動する。斜体の内容はカーソルが構文内にある場合も斜体表示を維持する。

## KaTeX

KaTeXは`trust: false`で実行する。次の上限を設ける。

- 数式入力長
- マクロ展開数
- 表示サイズ
- Decoration生成範囲

不正、巨大、または深くネストした数式は原文へフォールバックする。コード、コードブロック、リンク先URL、画像パスは数式解析から除外する。レンダリング結果はキャッシュする。

## 画像とリンク

ローカル画像は次の条件を満たす場合だけRust側でData URLへ変換する。

- 現在のMarkdownファイルのフォルダ配下
- canonicalize後もフォルダ外へ出ない
- 20 MB以下
- MIMEが画像

外部画像URLは取得しない。外部リンクとしてOSへ渡すのは`http`、`https`、`mailto`だけとする。

## PDF

PDFはMarkdownを正本とする派生出力である。

1. Markdownを印刷用HTMLへ変換する。
2. 編集画面と同じKaTeXと印刷CSSを使用する。
3. ローカル画像を制限付きでData URL化する。
4. PDF完了イベントの購読を開始する。
5. WebView2の印刷設定で背景色・背景画像の印刷を有効にし、`ICoreWebView2_7::PrintToPdf`で一時PDFへ出力する。
6. 完了イベントを待ち、成功時だけ同名PDFを置換する。
7. OSの既定アプリでPDFを開く。

印刷用のMarkdown変換コードは動的importし、通常起動のJavaScriptバンドルから分離する。コードフェンスに言語指定がある場合は印刷DOMへ言語ラベルを追加し、印刷CSSでは背景色の正確な出力を指定する。WebView2 COM相互運用は`pdf.rs`へ隔離する。完了待機の60秒タイムアウトは`PrintToPdf`開始後にだけ計測し、成功・失敗・タイムアウトの全経路でイベント購読とタイマーを解除する。

## ウィンドウとOS連携

- 半透明表示はWin32のlayered window属性で60%と100%を切り替える。
- 外部リンク、Explorer、PDFはWindows Shellへ渡す。
- Tauri Capabilityではメインウィンドウに必要なダイアログとイベントだけを許可する。
- フロントエンドへ任意のファイルシステム権限を与えず、用途を限定したRustコマンドを公開する。

## ビルドと配布

`scripts/build.ps1`を標準入口とし、処理を重複させず`scripts/build_tauri.ps1`を呼び出す。Tauri版ビルドは次を行う。

1. pnpm依存の固定確認
2. TypeScriptテストとlint
3. Rustテスト
4. Rustランチャーのreleaseビルド
5. Tauri本体のreleaseビルド
6. NSIS・MSI生成
7. 本体とランチャーを`dist`へコピー

`scripts/create_shortcut.ps1`を標準入口とし、指定されたホットキーを`scripts/create_tauri_shortcut.ps1`へ渡す。Tauri版スクリプトはスタートメニューショートカットとログオンタスクを登録する。ログオンタスクを登録できない場合だけ現在ユーザーの`Run`キーへフォールバックする。

## テスト方針

### 自動テスト

- 保存リビジョン競合
- BOM読み込み、BOMなし保存、保存失敗時の原本保持
- 実Markdownコーパスの原文一致
- 起動引数と単一起動転送
- ホットキー文字列の解析・正規化
- 数式の保護範囲、上限、フォールバック
- 入力支援と通常行におけるTabのフォーカス移動抑止
- 斜体の計算済みスタイルと疑似斜体設定
- ATX見出し抽出、階層構築、開閉状態、目次更新、見出し中央付近への移動
- 目次幅の上下限と40ピクセル単位の変更
- 大文書末尾までの目次解析と、本文変更時の古い解析処理の中止
- 日本語検索・置換、検索パネルの`Ctrl + F`開閉、入力欄での幅変更抑止
- 上部文書情報、全ショートカット一覧、外側クリックのDOM構成
- 外部画像遮断
- 10万文字・高密度数式の構文走査
- TypeScript型チェック、lint
- Rust全ターゲットClippy
- PowerShell構文

### 実機試験

- 非表示直後、5分、1時間、8時間、翌日の復帰
- 白画面・入力不能
- 完全終了後のホットキー再起動
- ホットキー競合と設定ロールバック
- 日本語IMEの未確定文字、変換、再変換、候補位置
- 表示倍率100%、125%、150%
- 異なるDPIの複数ディスプレイ
- 数式100個超、巨大・深い数式
- PDF生成・置換・既定アプリ起動

長時間試験が完了するまで、移行受け入れ記録では正式切り替え完了と判定しない。
